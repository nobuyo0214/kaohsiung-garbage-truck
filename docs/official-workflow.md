實際下載記錄在 `data/sources/access-results.json`：

- 高雄東區 CSV 真實下載連結在本環境回傳 HTTP **503**。JSON 連結由資料集公布，搜尋服務也發生逾時；登錄表保留實際網址，不另猜測端點。

- 搜尋服務取得的環境部頁面保存為原始文字快照，來源標記 `search-cache`／`cached`；取得時間是本次取得快取的時間，不是頁面官方更新日。
- PR #1 的 179 筆轉錄沿用並標記為未重新核實；其中 12 筆仍是 `stale`。未知取得時間及官方更新日期留空。

## 來源登錄與可重跑匯入

`data/sources/registry.json` 保存實際網址、原始格式、來源檔案範圍、資料集目錄、授權說明與快照位置。`zoneHint` 只是供人核對的提示，匯入器不將路線名稱數字轉成責任區或車次。未重新取得的已知來源列為 `not_collected`，不混入新日期。

```sh
npm ci --ignore-scripts
# 從已保存快照重建，完全不連外
npm run import:official
npm run report:expansion
# 下載一個已登錄來源；需要 Node.js 22+、curl，以及可存取該來源的網路環境
node scripts/official-import.cjs collect --source moenv-p0 --out work/live
# 可按來源檔案依序取得全部已登錄來源，每次請求間隔至少 0.5 秒
node scripts/official-import.cjs collect-all --file sanmin-east.csv --out work/live-east
```

下載器每次建立帶時間的 `.raw`、`.headers`、`.metadata.json` 與成功時的 `.csv`，保存網址、最終網址、HTTP 狀態、取得時間、雜湊及錯誤。失敗以非零狀態結束；批次取得有任一失敗也回傳非零，並保存成功與失敗清單，不偷偷以快取替代。HTTP `Last-Modified` 不自動當作官方更新日。

離線補充可使用瀏覽器另存的官方 HTML、官方 CSV 或 JSON：

```sh
node scripts/official-import.cjs import --source moenv-p0 \
  --format moenv-html --input work/saved-official.html \
  --metadata data/sources/templates/metadata.json --out work/offline
# 發現官方 HTML 中實際存在的路線連結，不產生猜測網址
node scripts/official-import.cjs discover --input work/route-list.html \
  --base https://hwms.moenv.gov.tw/dispPageBox/trans.aspx?ddsPageID=ROUTE \
  --out work/discovered
```

已支援 `moenv-html`、`moenv-text`（本次搜尋服務所見文字）、`csv`、`normalized-csv`、`json`。JSON 接受陣列或 `{ "records": [...] }`；其他結構需新增有文件的轉換器，不猜測巢狀資料。新來源在登錄表設定 `fields` 對應，例如 `zone`、`trip`、`place`、`time`、`days`、`route`、`routeName`、`sequence`、`source`、`updated`；`days` 必須明確指向一般垃圾欄位，程式沒有回收日回退。

HTML 以「清運點名稱描述」「一般垃圾」表頭找表格，不以固定欄序抓取。若缺表頭、路線識別、原始時間／地點欄或解析失敗，停止該來源匯入。工具不會執行匯入 HTML 的 JavaScript，也不使用登入、驗證碼或未公開端點。

`data/sources/templates/official.csv` 與 `metadata.json` 是空白補充格式，沒有虛構的站點、日期或網址。`acquiredAt` 只有知道真實取得時間才填寫；`officialUpdatedAt` 只有官方明確提供站點資料更新日才填寫。目錄詮釋資料日期保留在來源登錄表，不寫入站點官方更新日期。

每筆標準化結果保存：五欄、一般垃圾日、官方來源、官方路線／站序、來源 ID、穩定的來源紀錄 ID、`原始欄位` JSON、官方更新日期、資料取得時間及取得方式。完整輸入另外保存在原始檔，方便核查與重跑。

## 配對建議與安全邊界

精確日期配對繼續使用 `js/data-core.js` 的五欄機制。快取、未核實、過舊及其他非已核實狀態也會被批次配對器阻擋；既有 243 條規則及搜尋邏輯不因此被刪除。

新增的 `js/review-core.js` 只建立建議：

- 只在相同來源檔案內找候選；已提供行政區、責任區、車次時不跨組建議。
- 同名地點可列出不同時間；不同地點使用文字雙字片段相似度，搭配五分鐘內起點差或高度文字相似，最多列出 8 個候選。
- `delta` 為官方起點減 CSV 起點的分鐘差。相似度與分鐘差只影響建議排序，不用於日期授權。
- `time_extent_mismatch` 特別區分官方到點時間與 CSV 完整時段；不能補上猜測的離站時間。
- 分類可同時包含確認吻合、時間不同、缺少車次、停靠地點不同、資料衝突、找不到對應。一筆紀錄可有多種問題；篩選與報告不互斥。

## 管理員操作

1. 用 HTTP 開啟 `official-day-matcher.html`，上傳標準化 CSV，或按「載入三民東／西區與岡山試辦資料」。查詢站仍可照常使用。
2. 選擇行政區、官方路線、差異分類或審核狀態。清單每頁 40 筆，可使用關鍵字。
3. 選取官方紀錄與 CSV 候選，並排查看來源、責任區、車次、地點、完整時間與一般垃圾日。可開啟官方網址與原始欄位／取得資訊。
4. 明確精確吻合也必須填寫至少 10 字依據並核實官方欄位，才按「確認」。單純精確候選不會直接加入提案。
5. 尚未解決者保持待審核，或填原因後拒絕；可重新列為待審核。缺車次、時間不同及來源不可靠時，「確認」會保持停用。
6. 如另外取得完整官方證據，使用補充 CSV。除了五欄、一般垃圾日及官方來源，**必須填入 `對應來源紀錄ID`**，值為原官方紀錄在畫面／審核報告中的 ID。補充證據須完整精確匹配 CSV、日期一致、來源已核實且無日期衝突。僅網址、理由或勾選不能略過差異。
7. 可確認補充證據後，再匯出提案與審核依據 CSV。工具重新載入網站目前的全部原始 CSV 與日期表，重新檢查原始紀錄、證據、日期及已確認規則，保留其他維護者後來新增的規則。讀取失敗或已變更會停止匯出。

不得為了通過驗證，把 CSV 的車次或離站時間抄入「官方證據」；未確認的欄位必須留空。完整五欄補充證據需要實際官方資料支持，不能只是把兩個可能不同版本拼在一起。工具檢查欄位與一致性，維護者仍負責核對來源內容的真實性。

## 本機進度與多人交接

載入及審核後自動保存到此瀏覽器的 localStorage；完整保存官方資料、補充證據、確認／拒絕理由、證據指紋與未解決紀錄。可按「還原本機進度」繼續。

- 匯出／匯入版本 2 的進度 JSON，供備份或換裝置；不使用雲端帳號或付費服務。
- 瀏覽器空間不足或禁止保存會顯示提示，仍可下載 JSON。
- 還原不代表自動核准；匯出時會重新驗證。來源、補充證據、原始紀錄或既有日期改變，確認狀態無法通過提案驗證，必須重新審核。
- 拒絕不刪除原始資料。JSON 保留待辦與拒絕，審核報告與依據 CSV 可隨 PR 提交。
