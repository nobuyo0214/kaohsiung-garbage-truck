## 實際修改與限制

- 搜尋依原回收日字串及星期快取核心函式的結果，避免每筆每次重複NFKC與正規表示式；不改變核心對星期的解釋。今日時間軸快取完整時間解析，已按起始時間排序時不重排；來源時間改變會重新解析。
- 既有CSV記憶體快取、6工人並行、雜湊檢查、39檔完整性、30筆分批、附近索引與Haversine掃描、座標品質稽核均沿用。CSV解析、網路、附近掃描程式沒有調整，這些指標的差別視為量測變動，不能歸功於優化。
- 冷載入可操作中位數反而增加約4%，首批DOM未改善，索引成本略增；本次不能宣稱首次開啟變快。暖載入稍降，但區間重疊，不保證每台裝置都改善。主要可觀察改善是重複全市／單區回收篩選與時間軸。
- 初始傳輸增加8,593 bytes（約2%），為新介面程式。56,694 bytes未壓縮QR編碼器只在點擊時執行／載入；PWA首次安裝仍依原安全策略額外驗證快取全部25個介面資源，故未納入本表、也沒有宣稱安裝成本降低。3.1MB路線基準快照不由首頁下載；展開版本說明只取得小型index.json。
- Heap為Chromium的近似值，包含量測參考且受GC影響：冷快取下降、暖快取上升，不能推論記憶體已改善。未使用memory值作安全或測試判定。
- 這是模擬環境，不是實體手機或真實民眾遙測。保留所有原始樣本與範圍，不設CI毫秒上限；正確性由獨立回歸測試驗證。PWA另以真實Worker與子目錄回歸測試驗證。

## 重現

```bash
npm ci
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run measure:performance -- reports/performance/rerun.json
# 無系統Chromium時先 npx playwright install chromium，並省略上方環境變數
```

預設5次冷／暖配對，可用`PERF_RUNS`設定次數。要重測修改前，建立`3ddaac4`的獨立worktree，安裝該版依賴，再將本PR的`scripts/performance.cjs`複製到該worktree同路徑執行；前端維持原版。不要與其他瀏覽器測試或高CPU工作同時量測。結果依硬體和負載浮動，應比較相同設定多次樣本。
